# MIXING M3 — the first tool-calling leg (2026-08-23)

## Why this leg

Until today a tool-carrying request could only be served by a single-model
point: the route narrowed every frontier to `type === 'single'`, and the
sweep measured singles only under the tools filter. The measured
combinations — the part of the frontier no gateway has — never touched the
most valuable traffic a partner brings. M3 replaces the type check with a
capability per shape and lets a cascade carry tools (every stage gets them;
the stage that calls a tool answers). A combination may serve tool requests
only once it has been **measured on items that carried tools** — this leg.

## The instrument

`suites/v2/agentic-tool-use-tools-v1`: 24 authored items, each with 2 real
tool definitions where one is the obvious neighbour of the right one
(weather vs forecast, create vs list, send vs search, query vs describe,
read vs write, get vs refund, timer vs reminder). Scoring `tool-call`: 1.0
for the expected tool with every expected argument present and equal, 0.5
for the right tool with other arguments, 0 for text or another tool. Dates
resolve against a fixed "today" in the system prompt. No judge model — the
score is deterministic.

## What decides publication

A cascade earns a place on the served frontier only if, on this instrument,
it is within its confidence interval of the best single at a lower cost per
1K — the same rule every frontier point lives by — and its point then carries
`evidence.toolsMeasured`, which is what lets the route serve tool requests
from it.
